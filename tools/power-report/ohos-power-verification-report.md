# 鸿蒙示例页面静置出帧与功耗采样

测试日期：2026-10-17（北京时间）。由 Pi 操作真机，主会话复核关键截图、UI 文本及原始采样。

## 当前结论

五种已核实页面状态的正式静置采样各取得 30 个 SmartPerf FPS 读数，全部为 0；本次未复现持续 20 FPS 的现象。复制场景的第一次采样另有一次短暂 1–61 FPS 波动，保留为待归因发现，复测未再出现。**这些数据还不能单独证明原质量报告的 XComponent 冗余自绘制 buffer 已消除，也不是应用独立功耗值。**

## 正式采样结果

页面提前摆到指定状态，等待页面切换、键盘和提示条等有限动画结束，再采集约 30 秒。采样使用：

```powershell
hdc -t 192.168.68.207:46551 shell SP_daemon -N 30 -PKG com.azurekiln.qfli.java -f -c -p -print
```

`-f -c -p` 可在这台设备上组合使用。FPS、CPU 和电池读数来自同一次采集。

| 页面状态 | FPS 样本 | SmartPerf FPS 范围 | 进程 CPU 最高值 | 原始文件（captures/ 下） |
| --- | --- | --- | --- | --- |
| 主页“示例代码”列表静置 | 30 | 0–0 | 0.024414% | `list-20261017-015716.txt` |
| 示例 001 详情，代码未聚焦，预期输出可见 | 30 | 0–0 | 0.033267% | `detail-20261017-015849.txt` |
| 点击复制，提示条消失后静置（复测） | 30 | 0–0 | 0.083250% | `copy2-20261017-021117.txt` |
| 手动全选删除代码，再点击框外收起键盘 | 30 | 0–0 | 0.033036% | `clear-ok-20261017-021819.txt` |
| 返回列表并重进详情，原代码恢复后静置 | 30 | 0–0 | 0.025304% | `reenter-20261017-021937.txt` |

清空场景不是代码渲染成空白的猜测：`s4-final.json` 中代码字段文本长度为 0；截图 [s4-empty-keyboard-closed.jpeg](captures/s4-empty-keyboard-closed.jpeg) 同时显示空代码框、键盘已收起、预期输出仍在。

重进后 `reentered.json` 中代码恢复为原来的 186 字符，包含 `String[] args`；[scene6-reentered.jpeg](captures/scene6-reentered.jpeg) 已视觉复核。本轮未按“保存”，测试产生的临时代码编辑已随退出详情恢复。

### 可见光标对照

详情页聚焦代码框后，截图 [poscontrol-cursor.jpeg](captures/poscontrol-cursor.jpeg) 确认可见光标和键盘，代码仍是原始 186 字符。另采 5 秒，`poscontrol-20261017-022036.txt` 的 FPS 依次为 **1、0、0、1、0**，说明此采样路径能读到非零变化；该对照只启用 `-f`，不含 CPU 和电池区段。它不等同于对每个 XComponent buffer 的完整计数。

对照结束后点标题收起键盘，`final-state.json` 再次确认代码完整、未聚焦；手机操作已结束。

### 复制第一次采样的波动

`copy-20261017-020644.txt` 是需要保留的真实发现：第 7–13 个样本依次为 **1、60、61、60、60、60、57 FPS**，之后第 14–30 个样本恢复 0。采样开始前核对了正确详情页和复制提示，采样期间未发出 UI 操作；后续曾观察到前台应用自行变化，现有证据不足以确定该波动对应哪个表面或哪种动画。

不能仅因同期应用 CPU 较低便排除应用或渲染系统的问题，也不能将这段波动判成原报告的 20 FPS 异常。随后同场景复测 30 个样本均为 0。若质量平台仍报错，应对波动窗口追加带 surface 标识的原生帧追踪。

### 当前布局无法完成的一项

“代码框完全滚出屏幕后观察预期输出”在此竖屏示例 001 布局中记为 **不适用**，没有伪造通过：滚动视口 `[0,364]–[1272,2860]` 内，代码框约 `[56,602]–[1216,2040]`，预期输出约 `[56,2187]–[1216,2327]`，内容全部放得下，无法把代码框完全滚出视口。

本次详情、清空及重进采样均包含预期输出可见的状态，但没有单独完成真机“选中过预期输出后静置”的采样；该行为及完全离屏释放焦点另有本地 widget 回归覆盖。不能把本地回归写成真机验证。

## 怎样看这些读数

- **`fps`**：在核实前台页面之后读取的 SmartPerf FPS。静置时持续非零值得进一步追踪；点击、滚动、提示条和可见编辑光标可能产生正常绘制。
- **`refreshrate`**：本轮为 60 Hz，表示屏幕刷新频率，不能据此认为应用在画 60 帧。
- **`ProcCpuUsage`**：CPU 区段含目标 `ProcAppName`，可用于观察该进程的持续 CPU 工作；CPU 百分比不是瓦数。
- **`currentNow` / `voltageNow`**：整机电池电流/电压原始字段，包含屏幕、网络、系统和其他进程的影响，不能直接当成本应用独立功耗。

| 清空后外点 | -185 … -89 | 4053138 … 4059775 |

本机官方 SDK `D:/ProgramFiles/Huawei/OpenHarmony/Sdk/23/ets/api/@ohos.batteryInfo.d.ts` 对 `voltage` 注明 µV，对 `nowCurrent` 注明 mA。**SP_daemon 帮助没有证明其原始字段到该 API 的单位映射，因此不据此计算瓦数或应用耗电降幅。**

## 自己复测

1. 保持手机亮屏，手动进入目标应用和页面；静置场景先收起键盘，复制场景等提示条消失。
2. 保持应用前台、不触摸手机，在项目根目录运行：

```powershell
powershell -File tools/power-report/capture_scenario.ps1 -Scenario list
```

可将 `list` 改为 `detail`、`copy`、`clear-external` 或 `reenter`。无线调试端口变了就加 `-Target 192.168.68.207:新端口`。脚本只采样，不会自动切换页面，也不会仅凭 `-Scenario` 判断页面是否正确。

3. 查看输出的 FPS 最大值和非零样本数、进程 CPU 最高值及原始电池范围。完整数据保存到 `captures/`；缺少数字读数会明确显示“无样本”，不会算作 0 FPS。
4. 判断原质量问题是否通过，需在原质量平台重跑“前台不可见动效”检测。若复现，用原生帧追踪确认 `FlutterSurface / XComponent` 的具体 surface 及 buffer 提交，不能只看整屏刷新率。
5. 若需要应用归因的能耗记录，在本机 DevEco Studio 26.0.0.821 的 **Profiler** 工具窗口连接设备、选择应用，检查该设备/应用实际可用的能耗采集功能。本轮未完成 DevEco 能耗录制；也没有验证该 Release 包能附加每一种 Profiler。右侧 **Graphics Profiler** 窗口已从插件配置确认存在，是否能提供本问题所需的表面归因仍须实际采集验证。
